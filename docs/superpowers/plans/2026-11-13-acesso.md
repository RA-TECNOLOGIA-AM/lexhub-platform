# Acesso (cargo por unidade, equipes e grade por cargo) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A aba Acesso mostra o que cada cargo vê por unidade e deixa editar cargo por unidade, equipes e o papel de Desenvolvedor, direto no Supabase.

**Architecture:** Duas funções `security definer` no schema `api` (padrão de `20261113090000_membros.sql`), um `accessClient.ts` (rpc) e um mock em memória ligado ao `createMembersStore`. Regras puras em `accessEditor.ts` (prévia = mesma regra de `app_private.dashboard_scope`); componentes só montam.

**Tech Stack:** Postgres (Supabase vvhg) · React 19 + Vite + TS · Vitest · oxlint · Prettier (`--end-of-line auto`).

**Spec:** `docs/superpowers/specs/2026-11-13-acesso-design.md`

## Review Focus

1. **Gestor de U1 salvando alguém de U1+U2** — U2 (cargo e equipes) fica intacta. Teste no Task 1.
2. **Tirar o cargo de uma unidade com equipes marcadas** — as equipes daquela unidade saem juntas (front limpa; banco recusa equipe sem cargo). Testes nos Tasks 1 e 3.
3. **Pessoa que vira Desenvolvedor** — a prévia mostra "todas as unidades"; ao voltar a Membro, cargos por unidade continuam valendo. Teste no Task 3.
4. **Unidade sem nenhum dashboard ligado** — a grade mostra o estado vazio, não uma tabela sem linhas. Teste no Task 4 (`gridRows` vazio → mensagem).
5. **Quem não gere acesso** — 403 → matriz + aviso, sem tela de erro. Teste no Task 4 (`accessErrorView`).
