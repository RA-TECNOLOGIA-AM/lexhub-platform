# Membros (lista e convites no Supabase) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A aba Administração → Membros lista, convida, desativa/reativa e cancela convites com dados reais do Supabase; o convite vira acesso quando a pessoa entra com o Google.

**Architecture:** Funções `security definer` no schema `api` (mesmo padrão do Solicitar acesso, `20261112160000_solicitar_acesso.sql`), chamadas pelo front com `supabase.schema('api').rpc(...)` num módulo `membersClient.ts`. O mock implementa o mesmo contrato em memória. Lógica pura em `memberView.ts`/`invite.ts`; componentes só montam.

**Tech Stack:** Postgres (Supabase, staging vvhg) · React 19 + Vite + TS · Vitest · oxlint.

**Spec:** `docs/superpowers/specs/2026-11-12-membros-design.md`

## Global Constraints

- Branch `feat/membros`. **Nunca commitar nem dar push**: ao fim de cada tarefa, listar os arquivos e sugerir a mensagem; o Luís commita.
- Indentação de 4 espaços; comentários e textos de tela em pt-BR; comandos em PowerShell.
- Migration aditiva, com bloco de rollback comentado no fim. No vvhg: validar primeiro dentro de `begin; … rollback;` (migration + teste) via MCP `execute_sql`; aplicar (`apply_migration`) **só depois do "Aplica" do Luís**. Nunca merge do branch para produção.
- Funções novas: schema `api`, `language plpgsql security definer`, `set search_path = ''`, `revoke all … from public, anon`, `grant execute … to authenticated`.
- Erros: regra → `errcode = 'P0001'` com mensagem em pt-BR; sem permissão → `errcode = '42501'`.
- Convite vale 7 dias (`app.invitations.expires_at` default). Não existe e-mail automático.
- Editar cargo por unidade e equipes **não** é desta entrega (fica na aba Acesso).

## Review Focus

1. **E-mail com maiúsculas/espaços** no convite ou no Google (`Fulano@LexGroup.com.br `) — tem que casar com o convite (`lower(trim())` dos dois lados). Teste no Task 1 (aceite com e-mail em maiúsculas no JWT).
2. **Convidar quem já tem associação `invited` ou `disabled`** — `invited` vira ativa no aceite; `disabled` volta em `skipped` ("Desativado: reative na lista") e o aceite nunca reativa. Teste no Task 1.
3. **Gestor de duas unidades vendo membro de três** — a linha mostra só as unidades do escopo dele, e ele não desativa quem também é Owner/Dev. Teste no Task 1.
4. **Abrir a aba sem permissão** (colaborador) — 403 vira o estado "Você não gere membros nesta organização", não a tela de erro genérica. Teste no Task 5 (`membersErrorView`).
5. **Falha do `accept_my_invitations` no login** (schema `api` não exposto, rede) — o login segue e cai no `/me`. Teste no Task 2 (`session.test.ts`).

**Interfaces:**

- Produces (JSON em snake_case, igual aos tipos do Task 2):
  - `app_private.members_scope(p_org uuid) returns uuid[]`
  - `api.list_members(p_org text) returns jsonb` → `{ members, invitations, teams, units, can_invite_admin }`
  - `api.invite_members(p_org text, p_emails text[], p_role text, p_units text[], p_teams uuid[]) returns jsonb` → `{ invited: text[], skipped: [{ email, reason }] }`
  - `api.set_member_status(p_org text, p_member uuid, p_status text) returns jsonb` → o membro no formato da lista
  - `api.revoke_invitation(p_id uuid) returns jsonb` → `{ id, revoked_at }`
  - `api.accept_my_invitations() returns integer`

Formato de cada item:
- `members[]`: `{ id, name, email, org_role, units: [{ code, role }], teams: [name], status, last_seen_at, security }` — `security = 'Google'` quando `auth.users.raw_app_meta_data -> 'providers' ? 'google'`, senão `null`. Ordem: `status` (active, invited, disabled), depois `name`.
- `invitations[]` (só pendentes: `accepted_at is null and revoked_at is null and expires_at > now()`): `{ id, email, role, units: [code], teams: [name], invited_by, created_at, expires_at }` — `invited_by` = `full_name` da associação de quem convidou nessa org, senão o e-mail dele.
- `teams[]`: `{ id, name, unit }` (unit = código), só das unidades do escopo. `units[]`: `{ code, name }` do escopo.
- `can_invite_admin`: quem chama tem `members.manage` na org.

Regras (todas do spec, seção Banco):
- `members_scope`: todas as unidades ativas da org se a org está em `my_org_ids_with('members.manage')`; senão `my_unit_ids_with('unit.members.manage')` ∩ unidades da org. Funções públicas com escopo vazio → 42501 `'Você não gere membros nesta organização.'`.
- `p_org` é slug; slug inexistente → 42501 (não revela se existe).
- `invite_members`: e-mails `lower(trim())`, sem vazios nem repetidos; `p_role` em `admin|gestor|controller|colaborador|leitor` (`owner`/`member`/outro → P0001 `'Papel inválido.'`); `admin` sem `members.manage` → 42501; cargo de unidade com `p_units` vazio → P0001 `'Escolha ao menos uma unidade.'`; unidade fora do escopo → 42501; equipe cuja unidade não está em `p_units` → P0001 `'Equipe fora das unidades escolhidas.'`. `skipped` com `reason`: `'Já faz parte da organização'` (associação `active`), `'Desativado: reative na lista'` (`disabled`), `'Já tem convite pendente'`. Convite grava `token_hash = gen_random_uuid()::text`, `invited_by = auth.uid()`. Auditoria `member.invited` por e-mail.
- `set_member_status`: `p_status` em `active|disabled`; recusa (P0001) desativar a si mesmo (`'Você não pode desativar a si mesmo.'`) e desativar o último owner/admin ativo (`'A organização precisa de ao menos um Owner ou Desenvolvedor ativo.'`); membro sem unidade no escopo, ou Owner/Dev quando quem chama não tem `members.manage` → 42501. Auditoria `member.disabled` / `member.enabled`.
- `revoke_invitation`: convite pendente com `unit_ids` cruzando o escopo (ou org com `members.manage`); senão 42501; já aceito/revogado → P0001 `'Convite não está mais pendente.'`. Auditoria `invitation.revoked`.
- `accept_my_invitations`: e-mail = `lower(trim(auth.jwt() ->> 'email'))`; age só se `(auth.jwt() -> 'user_metadata' ->> 'email_verified')::boolean` é true; senão devolve 0. Para cada convite pendente e válido do e-mail, numa org ativa: associação existente `disabled` → pula (convite fica pendente); `invited` → vira `active`; inexistente → cria com `full_name` = `user_metadata.full_name` ou `name` ou o e-mail, `role_key` = `admin` se o convite é `admin`, senão `member`. Cargo de unidade → `membership_units` em cada `unit_ids` com o `role_key` do convite (`on conflict do nothing`); `team_ids` → `membership_teams`. Marca `accepted_at`. Auditoria `invitation.accepted`. Devolve a contagem.
